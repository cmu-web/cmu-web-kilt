Template Quirks

Things CMU's template does that can surprise you, and how to work with them. The kit fixes some of them itself.

Note

The template belongs to University Communications & Marketing, and sites load it from www.cmu.edu, so this kit can't change it. Where it can, this kit works around a quirk; otherwise this page says how you can. We track the ones that affect this kit as upstream issues.

The Template's Script

  • Escape doesn't close the menu. The script's Escape listener calls the menu's toggle without the argument that makes it act. The kit closes the menu on Escape. Under Turbo, the script runs again on every page Turbo shows and adds another listener each time; the kit answers Escape before any of them, so the menu toggles once even if the template's listener is fixed.
  • It opens the menu by itself. On a screen wider than 960 pixels, the script opens the menu when the page is in a submenu, is a tab with a submenu or is a menu-only item, and the menu covers half the page. With cmu-app.js, add data-cmu-menu="closed" to <body> and the menu starts closed, under Turbo too. Opened by hand, it still shows where the page is.
  • Under Turbo, a page from Turbo's cache breaks the header. The script rearranges the header each time it runs, and a cached page was already rearranged. Turn the cache off, as the Rails install shows.
  • It clears local storage on every page. When it sets up its list filters, it empties the browser's local storage, whether or not the page has filters. On a server that many sites share, that wipes what all of them saved. Keep what a page remembers in a cookie or in session storage instead; the kit's tabs keep the chosen tab in a cookie for this reason.
  • It breaks in-page links. It turns every link to a section (href="#id") into javascript:void(0) and scrolls with its own animation, so the address never shows the section and Back doesn't return. With cmu-app.js, the links stay real.
  • It removes style="" from spans. Use a div when you need an inline style, such as a bar's width.

Markup

  • .content lays out its direct children as columns. Put one wrapper <div> inside it.
  • A logo or a sidebar has to touch the element before it. A logo in the header follows the site name's <div>, and a sidebar follows the page's <div> in .content (</div><div class="sidebar">), with no space or line break between them. Otherwise it drops below.
  • …but a formatter can undo that. Prettier and similar tools put a line break between those pairs. Put <!-- prettier-ignore --> right before the site name's <div> and before the .content block, so it leaves them as written.

Styles

  • Tables don't stretch. They're display: block so they scroll on phones. Add cmu-full to stretch one to full width from 768px up.
  • Alerts are red. The template makes any div or p with role="alert" red, with !important. The kit's flash messages keep their own colors.
  • Classes that set display beat hidden. .btn and others override a bare hidden attribute. The kit makes hidden always hide.
  • Search's magnifier is white. It shows on a red or gray roof but disappears on a white one. The kit darkens it there.
  • Any field with the placeholder “Search” gets that white magnifier inside it, where it can't be seen. Except in the site search at the top of the page, the kit draws the same magnifier in gray, in every search box.
  • The external-link mark and contact icons are dark, made for white pages. The kit makes them white on a dark section.

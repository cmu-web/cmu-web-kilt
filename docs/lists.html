Lists and Tables

Tables with and without actions, files to download and folded lists, and the tools for finding things in a long one: search, filters, Load More and pages.

Tables CMS

Use the template's table.alternate for striped rows. Add cmu-full to stretch a table to full width from 768px up (below that, the template lets it scroll sideways). cmu-compare splits a two-column table evenly, for before-and-after comparisons. Cells are centered top to bottom, so a one-line cell sits level with a wrapped one or a picture beside it; to center pictures of different widths across their column too, add the template's aligncenter to those cells.

Give every table a header row, with <th scope="col"> for each column, so screen readers can say which column a cell is in. A column of buttons gets a header too, hidden with sr-only, such as "Actions."

Options, for a table in an app (they need cmu-app.css, cmu-app on the body and cmu-app.js): add data-cmu-table to the table, then any of sorting, filtering, a count, the view in the page's address, a sticky header and server paging. Each works on its own, and without the script the table shows every row in its first order.

Sorting

Give a column's heading data-sort-key and put its words in a button.cmu-sort with an empty span.cmu-sort-arrow. Clicking sorts by that column, and clicking again reverses it; the heading turns red, shows ▲ or ▼ and gets aria-sort. Numbers sort as numbers, even with a dollar sign or commas. For a cell whose words don't sort well, such as a date, put the value to sort by in data-sort-value. Click a heading:

Filtering

A search box for the whole table is an <input> with data-cmu-filter set to the table's id, placed as a search. For a box per column, add a tr.cmu-filter-row to the table's head with an <input data-cmu-filter-column> under each column that needs one, named like the column's data-sort-key (or data-cmu-column on a heading that doesn't sort), and a label for screen readers. Rows match as people type, words in a row's data-keywords match too, and hidden rows move to the end so the stripes stay even. Type in any of the boxes:

The Count

An element with data-cmu-count set to the table's id, under the table with aria-live="polite", says how many rows show after each change, as in the example above. Name the rows with data-cmu-noun on the table, as one word or as "person|people" where the plural isn't just an s. Write the first count into the page too, for people without the script.

Style

Use the same words as other counts: “Showing all 5 checkouts,” “Showing 2 of 5 checkouts,” “Showing 1 checkout” and, with nothing found, the template's “Sorry, no results to display.”

The View in the Address

The search, the column filters and the sort go in the page's address as people change them, and come back from it when the page loads, so a filtered, sorted table can be bookmarked and shared: ?q=drill, ?filter[organization]=booth, ?sort=due and ?sort=-due for the reverse. On a page with more than one table, give each a name in data-cmu-table, and its settings go under that name (?checkouts[q]=drill). Frameworks such as Rails read these as nested parameters.

Sticky Header

Add cmu-sticky to a long table, and its head, with any filter row, stays at the top of the window as people scroll down the rows. It works from 768px up, with cmu-full; below that the table scrolls sideways instead.

Long Tables

Sorting and filtering in the browser suit a table of up to a few thousand rows sent with the page. For a longer one, let the server do it with the same markup and the same address parameters:

  • Add data-cmu-table-server to the table. The script then leaves the rows alone, and typing in a filter submits its form after a pause.
  • Put the filter boxes in a <form method="get"> named q and filter[organization], with a Search button for people without the script.
  • Make each sorting heading a link (a.cmu-sort) to the same page with ?sort= set, and mark the current one with aria-sort and its arrow.
  • Page the rows on the server, with a count over them and a pager or Load More under them.

Tables With Actions AppScript

The bulk bar sits on top of a table.alternate: the selection count, then actions for the selected rows. Its height is fixed, so buttons appearing don't push the table down. Each row gets one button, the next thing to do, and a ⋯ menu with the rest; a row with nothing else to do gets no menu.

Classes

cmu-bulk-bar, cmu-selection-count, cmu-has-selection, cmu-select-cell, cmu-sort, cmu-sort-arrow, cmu-fit, cmu-row-buttons, cmu-row-menu, cmu-row-menu-list, data-cmu-menu, num

  • One button per row: solid for something missing (Upload Syllabus), outlined when it's there (Replace Syllabus), at one fixed width and the height of a two-line button so rows stay even.
  • The ⋯ menu (cmu-row-menu) holds the row's other actions, in the bulk bar's words: a button for each, or a link for one that goes somewhere. Name the ⋯ button for screen readers ("More actions for 15-112 A") and give it a matching title. cmu-app.js opens it, one at a time; a click elsewhere or Escape closes it.
  • Something to open, such as a file, gets a plain link in a column of its own before the actions, with its type after it: "View [PDF]." Keep the row's title plain text. Hide the column's header with sr-only and name what the link opens ("Syllabus"); the actions column's hidden header is "Actions."
  • Selection: the app's script keeps the count current ("No sections selected" when there are none), adds cmu-has-selection to it when anything is selected and shows each bulk button only when it applies to a selected row, with how many: "Upload Syllabus (2)." Try it above.
  • Checkbox cells: the label fills the cell, so the whole cell is the click target.
  • Sorting: put data-sort-key on the header and a button.cmu-sort inside it; set aria-sort on the sorted column. For filtering, see Filters.
  • cmu-fit shrinks a column to its content. num (on th and td) right-aligns numbers.
  • Keep labels together with &nbsp;, so "a" never ends a line inside a button.

File Table CMS

A list of forms or documents to download, with when each was last changed. Use table.alternate with real column headings, and put the file type after each link in plain text. Don't put the links in <h4> headings to make them stand out, since screen readers then announce every row as a heading. A long page of them can go under collapsed headings, as below.

Folded Lists App

A <details> whose summary reads as a line of text ending in a bold toggle with a chevron, which points down while closed, flips up when open and turns red on hover. It opens right there, so it doesn't look like a call to action to another page. Closed, the toggle names what's hidden; open, it says how to fold it back. It slides open and closed where the browser supports that (not for people who turn motion down). Tabs fold the same way.

Classes

cmu-more, cmu-more-link, cmu-more-closed, cmu-more-open

Search App

One search box over a list: a sentence saying what the user can search by, then a box across the full width, searching as people type. The sentence does the label's job on screen, so the <label> is for screen readers only (sr-only). The placeholder says what you'll find, ending in an ellipsis. The box gets the template's magnifier, in gray.

Filters App

A row of filter groups above a list, each with a small label over a search box or checkboxes. A group with a text box takes the row's spare width; two or more split it, and wrap on a narrow screen. For a single search box, use a search instead.

Load More App

A button under a long list that adds the next batch to it, after a count of what's showing. It suits browsing and search results, where people scan down. For a list people need to come back to a place in, use Pagination instead.

The app loads the results and updates the count; it doesn't depend on the template's script. Load More is a ghost button half the page wide, and the full width on phones. Hide its paragraph (hidden) once everything is showing.

Style

Name what the button loads, with the same noun as the count: “Load More Sections.”

Pagination App

One batch of results at a time, each with its own address, under a count of what's showing. It's for a list people come back to a place in, or one that's too long to keep adding to with Load More.

A pager is one list: first («), previous (‹), the page numbers, next (›) and last (»). Mark the current page with aria-current="page", and give each arrow an aria-label ("First page" and so on) for screen readers. An arrow that goes nowhere, such as previous on the first page, keeps its place but loses its href and gets aria-disabled="true", which grays it out. Keep the numbers to seven slots, so the pager stays the same width as people move through: the first page, the last and the pages around the current one, with an ellipsis for each gap (1 2 3 4 5 … 16 near the start, 1 … 7 8 9 … 16 in the middle, 1 … 12 13 14 15 16 near the end). With seven pages or fewer, show them all. Use the same batch size as Load More, such as 20. On phones, « and » give way to the numbers.

cmu-results-count, cmu-pager
